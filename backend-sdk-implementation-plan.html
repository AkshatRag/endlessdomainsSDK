Backend Engineering Plan

Endless Domains Login SDK: NestJS Backend Implementation Roadmap

Grounded specifically in the endless-domain-api repository (NestJS 10, TypeORM, PostgreSQL, Alchemy SDK, AWS Secrets Manager). This document outlines the exact modules, entities, services, DTOs, and controllers to build.

1. Reusing Existing Backend Infrastructure

We do not reinvent the wheel. Our backend already possesses the core building blocks needed for this SDK:

Need Existing Repository File / Module How We Reuse It
Nonce & Wallet Verification src/components/web3-auth/web3-auth.service.ts Reuse the nonce generator and ECDSA signature recovery math (ethers.verifyMessage). We bind it to EIP-4361 standard SIWE format.
Polygon On-Chain Reads src/components/alchmey/ud-alchmey/ud-alchmey.serveice.ts Reuse UdAlchmeyService, configured with Network.MATIC_MAINNET and ALCHMEY_KEY from ConfigService, for sub-second contract reads.
Domain Candidate Lookup src/components/domain/domain-detail/domain-detail-bc.repo.ts Query candidate domains from tbl_domain_detail_bc (indexed by wallet address) before running live on-chain checks.
Logging & Monitoring src/logger/file-logge.ts (CustomLoggerService) Inject CustomLoggerService for CloudWatch error and audit logging.
Database & Entity Pattern src/@core/common/entity/base.entity.ts Extend BaseEntity (providing id, createdDateTime, isDeleted, lastChangedDateTime).
Controller Response Envelope src/@core/common/dto/response.dto.ts Wrap all responses in standard new Response(MessageEnum, result).

3. Step-by-Step Implementation Roadmap

Phase 1: Database Entities & TypeORM Migration

Days 1 - 2

Goal: Establish database tables in PostgreSQL matching the plan data model.

  • Create tbl_login_clients: stores clientId, clientName, redirectUris (text[]), allowedOrigins (text[]), requireDomain (boolean).
  • Create tbl_login_transactions: stores active login handshakes, PKCE code_challenge, nonce, and 10-minute expiry.
  • Create tbl_login_codes: stores 60-second single-use authorization codes.
  • Create tbl_login_refresh_tokens: stores argon2-hashed refresh tokens, family IDs, and rotation replacement pointers.
  • Create tbl_login_consents: records player consent per game.
  • Migration Command: Run npm run typeorm:migration:generate -- -n CreateLoginProviderTables, then npm run typeorm:migration:run.

Phase 2: ES256 Asymmetric Key Service & JWKS Endpoint

Days 3 - 4

Goal: Issue cryptographically verifiable JWTs without exposing private keys.

  • Generate an ES256 (NIST P-256) keypair. Store private key in AWS Secrets Manager or KMS; store public JWK in tbl_login_signing_keys.
  • Implement GET /.well-known/jwks.json: returns active public keys so game backends can verify tokens offline.
  • Implement GET /.well-known/openid-configuration: standard discovery document returning issuer, endpoints, and supported claims.

Phase 3: Wallet SIWE Verification & Polygon .og Domain Service

Days 5 - 7

Goal: Verify wallet signatures for free (0 gas) and verify .og domain ownership live on Polygon.

  • Implement GET /api/login/nonce: generates a random 16-byte nonce tied to transaction ID.
  • Implement POST /api/login/verify: parses EIP-4361 SIWE message, checks domain/URI/nonce/expiry, recovers signer address with ethers v5/v6, and sets HttpOnly session cookie.
  • Implement DomainOwnershipService:
    1. Fetch candidate domains from tbl_domain_detail_bc.
    2. Call Polygon contract 0xa9a6A3626993D487d2Dbda3173cf58cA1a9D9e9f via UdAlchmeyService to verify ownerOf(namehash) and expiryOf(tokenId).
    3. Call reverseNameOf(wallet) to designate primary domain.
    4. Cache results for 60 seconds using @nestjs/cache-manager.

Phase 4: OIDC Core Endpoints (/authorize & /token)

Days 8 - 10

Goal: Complete standard PKCE authorization code exchange and token issuance.

  • Implement GET /authorize: validates client and PKCE challenge, redirects to hosted login UI.
  • Implement POST /api/login/consent: records domain choice, generates 60s authorization code.
  • Implement POST /token:
    • For grant_type=authorization_code: validates SHA256(code_verifier) === code_challenge, burns code.
    • Computes Pairwise Sub: HMAC_SHA256(client_id, walletAddress).
    • Issues 1-hour ES256 ID Token & 7-day rotating Refresh Token.
    • For grant_type=refresh_token: rotates token; re-checks on-chain Polygon ownership; if transferred, sets domain_status: "lost" (Decision D3).

Phase 5: Client SDK Packages (@endlessdomains/login & login-verify)

Days 11 - 13

Goal: Publish lightweight npm packages and CDN scripts for games.

  • @endlessdomains/login (<15KB gzip): PKCE generator, popup modal with postMessage, automatic redirect fallback, token refresh timer.
  • @endlessdomains/login-verify: lightweight verifier caching /.well-known/jwks.json for Node/Express game servers.

Phase 6: Pilot Integration with Endless Vault

Days 14 - 15

Goal: Prove the full flow in a live game.

  • Register endless-vault in tbl_login_clients.
  • Replace unverified #idIn text box in endless-vault_14 1.html with login.renderButton().
  • Update pilot HUD to display verified .og domain and unlock Tier 3 Gold Armor!

4. Registration in app.module.ts

Once built, register the module in src/app.module.ts like any standard feature module:

// src/app.module.ts
import { LoginProviderModule } from '@components/login-provider/login-provider.module';

@Module({
  imports: [
    // ... existing modules
    Web3AuthModule,
    UDIntegrationModule,
    LoginProviderModule, // <-- Add Login Provider here
  ],
})
export class AppModule {}
