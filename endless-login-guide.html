1. The Problem in Endless Vault vs. The SDK Solution

❌ The Current Problem

In endless-vault_14 1.html, pilot identity is just a plain, unverified HTML text box (#idIn):

  • Anyone can click "change identity" and type vitalik.eth or satoshinakamoto.og.
  • The game blindly unlocks high-rarity Tier 3 & 4 Gold Armor, special halos, and particle effects.
  • Multiplayer leaderboards are completely spoofable with zero cryptographic proof.

✅ The Login SDK Solution

Replaces the unverified text box with an official "Sign in with your domain" button powered by @endlessdomains/login:

  • Player signs a free, 0-gas cryptographic message in MetaMask (EIP-4361).
  • Endless Domains verifies on-chain that the wallet owns akshat.og on Polygon.
  • The game receives a tamper-proof JWT token. Legit domain owners get verified bragging rights!

2. Why .og Domains Instead of .eth?

💡 The Core Takeaway

.og is the #1 PRIMARY domain of this entire project! When the plan mentions "Sign In With Ethereum (SIWE)", it is only referring to the wallet signature math standard (0x addresses). The domain name you are signing in with is .og on Polygon!

3. The 5 Actors on the Whiteboard

When presenting on the whiteboard, clearly explain these 5 distinct entities:

Actor Real-World Piece What It Does in Plain English
1. Game Client Endless Vault + @endlessdomains/login The frontend game. Under 15KB bundle. Doesn't need wagmi or ethers. Simply calls login.signIn().
2. Player Wallet MetaMask / AppKit / Coinbase Holds the cryptographic private key. Signs the EIP-4361 text message. Free, 0 gas, zero money moves.
3. Login Service login.endlessdomains.io (NestJS) The brain. Issues single-use nonces, validates signatures, queries database, and signs JWT tokens with AWS KMS keys.
4. Blockchain Polygon Smart Contract (Chain 137) The ultimate source of truth. Calls ownerOf(namehash) and expiryOf(tokenId) in real time.
5. Game Server Game Server + @endlessdomains/login-verify The verifier. Inspects the ID Token against /.well-known/jwks.json so high scores cannot be cheated.

4. How it Works: Detailed Step-by-Step Architecture (1 to 10)

Every single step of the login protocol broken down from two perspectives: What the player experiences on screen, and what the cryptographic systems execute behind the scenes.

1

Game Initiates Login & Generates PKCE Challenge

Protocol Endpoint: GET /authorize
ACTOR: GAME CLIENT SDK
👀 What the Player Sees:

In Endless Vault, the player clicks the blue branded button: "Sign in with your domain". A clean browser popup window opens pointing to login.endlessdomains.io.

⚙️ Under the Hood (Technical Math):

The SDK generates a random 64-character secret in browser memory: code_verifier. It computes the SHA-256 hash of this string to create the code_challenge. It also creates a random CSRF state token and appends them to the authorization URL.

💡 Why this matters: The game never has to bundle heavy wallet libraries or manage private keys. By using PKCE, the secret verifier stays safely inside the game's memory and is never exposed in the URL. 
GET /authorize?client_id=endless-vault
  &redirect_uri=https://endlessvault.game/callback
  &response_type=code
  &scope=openid%20profile%20wallet
  &state=st_81c7f4e9a0b3
  &code_challenge=E9Mel-audo7wXuU61ueErDwQLKerDEPfkXYqJMVwmEB
  &code_challenge_method=S256
2

Hosted Login Page Displays Game & Prompts Wallet Connect

Hosted Interface: login.endlessdomains.io
ACTOR: LOGIN SERVICE
👀 What the Player Sees:

The popup displays: "Endless Vault wants you to sign in with your domain" alongside the game's official logo. The player chooses their wallet: MetaMask, Coinbase Wallet, or scans a QR code with their mobile phone.

⚙️ Under the Hood (Technical Math):

The login service runs on its own secure subdomain (login.endlessdomains.io). It checks tbl_login_clients to verify that endless-vault is an approved game client and that the redirect URI exactly matches the registered whitelist.

💡 Why this matters (Decision D4): Running on its own subdomain with strict HTTP headers (Content-Security-Policy: frame-ancestors 'none') guarantees that malicious sites cannot embed our login page inside an invisible iframe to steal clicks (anti-clickjacking).
3

Login Service Issues a Single-Use Nonce & SIWE Challenge

Internal API: GET /api/login/nonce
ACTOR: LOGIN SERVICE
👀 What the Player Sees:

The screen shows: "Preparing secure signature... (Free, 0 gas)" while MetaMask opens its prompt.

⚙️ Under the Hood (Technical Math):

The backend creates a cryptographically strong, random 16-byte nonce string (8f2c4a91e0b74d1a) bound to this specific login transaction ID. It sets a strict 5-minute expiry in Redis/Postgres.

💡 Why this matters: The nonce acts as a one-time barcode. If a malicious observer on the same network sniffs the signature, they cannot replay it tomorrow because the server marks this nonce as burned after one use.

4

Player Signs EIP-4361 Message (Free, 0 Gas)

Verification API: POST /api/login/verify
ACTOR: PLAYER WALLET
👀 What the Player Sees:

MetaMask displays the human-readable text explaining what game they are entering. The player clicks the blue Sign button. No gas fee or transaction fee is charged.

⚙️ Under the Hood (Technical Math):

MetaMask calculates an ECDSA signature over the secp256k1 curve. The signature is sent to POST /api/login/verify. The NestJS backend calls ethers.verifyMessage(), recovers the public address 0x8FD5...Be4D0, confirms it matches, burns the nonce, and sets an encrypted session cookie.

💡 Why this matters: Zero barrier to entry. Players do not need MATIC or POL in their wallet to sign in, making web3 game onboarding completely frictionless.
5

On-Chain Polygon Ownership Verification

Smart Contract: 0xa9a6...9e9f (Polygon 137)
ACTOR: BLOCKCHAIN (POLYGON)
👀 What the Player Sees:

A smooth 0.3-second pulse animation: "Verifying your .og domains on Polygon...".

⚙️ Under the Hood (Technical Math):

The backend pulls candidates from tbl_domain_detail_bc, computes namehash("akshat.og"), and makes a live read-only eth_call via Alchemy to the Polygon Unstoppable Domains registry:
• ownerOf(tokenId) $\rightarrow$ returns 0x8FD5...Be4D0 (Match!)
• expiryOf(tokenId) $\rightarrow$ returns 0 (Perpetual / Active)
• reverseNameOf(wallet) $\rightarrow$ returns akshat.og (Primary domain)

💡 Why this matters: We never trust stale database records alone. Live on-chain verification guarantees that if a domain was sold or transferred 2 minutes ago, it cannot be used to spoof an identity.
6

Player Selects Verified Domain & Approves Consent

Consent API: POST /api/login/consent
ACTOR: LOGIN SERVICE
👀 What the Player Sees:

The player sees their confirmed domain cards: akshat.og (tagged with a cyan PRIMARY badge) and vaultking.og. Below, they see: "Endless Vault will receive: Your domain name and wallet address." They click Confirm & Enter Game.

⚙️ Under the Hood (Technical Math):

The backend records consent in tbl_login_consents so returning players can skip this step in the future. It generates a single-use 60-second authorization code (ac_9f82c47a...) tied to the PKCE code_challenge from Step 1.

💡 Why this matters (Decision D8): Players who don't own an .og domain yet are allowed to sign in as "Wallet-Only" (showing their short wallet address). A prominent button invites them to "Claim your .og name on Endless Domains", turning gamers into marketplace customers.
7

Login Service Delivers Authorization Code via postMessage

Browser Bridge: window.opener.postMessage
ACTOR: LOGIN SERVICE
👀 What the Player Sees:

The popup window briefly displays a green checkmark and automatically closes, bringing the game back into focus.

⚙️ Under the Hood (Technical Math):

The popup script executes:
window.opener.postMessage({ type: "ENDLESS_LOGIN_CALLBACK", code: "ac_...", state: "..." }, "https://endlessvault.game"). The SDK verifies the origin strictly matches https://login.endlessdomains.io and confirms the returned state matches the original state token.

💡 Why this matters (Decision D5): In WebGL and 3D browser games, a full-page redirect forces the browser to reload all 3D assets, textures, and sounds, resetting the game. Using postMessage keeps the 3D game loaded in memory without interruption.
8

Game SDK Exchanges Code & PKCE Verifier for Tokens

Token Endpoint: POST /token
ACTOR: GAME CLIENT SDK
👀 What the Player Sees:

A quick status in the corner of the game: "Securing session..." for about 150 milliseconds.

⚙️ Under the Hood (Technical Math):

The SDK calls POST /token sending the authorization code alongside the original unhashed code_verifier. The backend computes SHA256(code_verifier). If it equals the code_challenge from Step 1, the code is burned and the transaction succeeds.

💡 Why this matters: This is the cryptographic core of PKCE. Even if a rogue browser extension intercepted the authorization code from Step 7, it cannot exchange it for tokens because it does not possess the secret code_verifier stored in the game's memory! 
POST /token HTTP/1.1
Host: login.endlessdomains.io
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=ac_9f82c47a10b3e5d7
&code_verifier=dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk
&client_id=endless-vault
&redirect_uri=https://endlessvault.game/callback
9

Login Service Issues ES256 Signed Identity & Refresh Tokens

Security Standard: ES256 (ECDSA P-256 JWT)
ACTOR: LOGIN SERVICE
👀 What the Player Sees:

The game receives the player's identity and avatar.

⚙️ Under the Hood (Technical Math):

The backend uses an asymmetric ES256 private key stored in AWS KMS to sign an ID Token (JWT valid for 1 hour). It also issues a rotating Refresh Token (valid for 7 days) and returns them to the browser SDK.

💡 Why this matters: The ID Token is a self-contained, digitally signed credential. Any server can inspect its claims and trust it implicitly without needing to query our database every single second.

  "access_token": "at_7c1d9b3a0e4f218c",
  "refresh_token": "rt_4f2a8e1b9c7d0a3e"
}
10

Game Server Verifies Token via JWKS & Unlocks Gold Mech

Verification Public Keys: /.well-known/jwks.json
ACTOR: GAME SERVER & VERIFIER
👀 What the Player Sees:

Endless Vault plays a triumphant sound sting! The player's identity badge switches from guest.og [unverified] to akshat.og [VERIFIED]. Their mech upgrades to Tier 3 Gold Halo Armor with engraved plating and gold lightning bolts!

⚙️ Under the Hood (Technical Math):

When submitting scores or joining multiplayer, the game sends the ID Token in the Authorization: Bearer header. The game server downloads public keys from https://login.endlessdomains.io/.well-known/jwks.json and validates the cryptographic signature offline.

💡 Why this matters: Zero-trust architecture. Even if a player modifies their local browser memory with cheat tools to say "akshat.og", the game server will reject their score unless it is backed by an authentic, KMS-signed ID token.

  audience: 'endless-vault'

// claims.domain_status = "owned"

7. The Complete Jargon Buster: Every Technical Term Explained

Everything in this project broken down into simple, real-world analogies so you can speak with 100% confidence in front of Mohit sir and the senior engineers.

Group 1: Wallet & Identity Verification (SIWE, EIP-4361, Nonce)

SIWE (Sign-In with Ethereum) & EIP-4361

IDENTITY STANDARD

Plain-English Analogy: A digital notary stamp. Instead of typing a password that can be stolen, your MetaMask wallet holds a private key. You sign a piece of plain text with your key to prove you own the wallet.

In our Login SDK: EIP-4361 is the official Ethereum Improvement Proposal that created a standardized format for this message (specifying domain, wallet address, URI, chain ID, and nonce).

Key Meeting Point: "SIWE is completely free and takes 0 gas! It doesn't submit a transaction to the blockchain; it just does cryptographic math in the browser."

NONCE ("Number used ONCE")

ANTI-REPLAY SECURITY

Plain-English Analogy: A movie ticket with a timestamp and barcode. Once the usher tears it, nobody else can sneak into the theater using that same ticket.

In our Login SDK: The login backend generates a random string (e.g. 8f2c4a91...) valid for exactly 5 minutes. The wallet includes this nonce inside the signature. Once verified, the backend marks it as used.

Why we need it: Prevents "Replay Attacks". Even if a hacker records your signature over WiFi, they cannot reuse it because the server will reject an already-used nonce.

Group 2: The Authentication Protocol (OIDC, OAuth 2.0, PKCE)

OIDC (OpenID Connect) & OAuth 2.0

AUTH PROTOCOL

Plain-English Analogy: Showing your government-issued ID card at a hotel desk. OAuth 2.0 is the hotel keycard that lets you open the room door (authorization); OIDC is the passport that proves who you are (identity).

In our Login SDK: This is the global standard used by Google, Apple, and Microsoft. By adhering to OIDC, any game engine (Phaser, Unity WebGL, Unreal) can integrate Endless Domains without writing custom authentication logic.

PKCE (Proof Key for Code Exchange)

BROWSER SECURITY

Plain-English Analogy: A secret handshake between friends. You lock a box with a special padlock (the code_challenge) and send it across the room. When the receiver comes back, they can only open it if they have the original secret key (the code_verifier).

In our Login SDK: Web games are public clients—they cannot keep a secret API key safe in browser JavaScript. PKCE solves this: the game generates a random secret in memory (code_verifier), sends its SHA-256 hash (code_challenge) to the login popup, and only exchanges the final code by revealing the verifier.

Key Meeting Point: "PKCE stops malicious browser extensions or man-in-the-middle attackers from intercepting login codes."

Group 3: Blockchain Infrastructure & Domain Reading (Alchemy, RPC, Namehash)

ALCHEMY & RPC (Remote Procedure Call)

BLOCKCHAIN BRIDGE

Plain-English Analogy: A high-speed internet pipeline directly to the Polygon blockchain library. Instead of our backend having to download 500 gigabytes of blockchain data to run a full node, we ask Alchemy's servers to read the data for us.

In our Login SDK: When our backend needs to know if a wallet owns akshat.og, it makes an RPC eth_call via Alchemy to execute a read-only smart contract check in under 400 milliseconds.

SMART CONTRACT REGISTRY & ownerOf(tokenId)

POLYGON CONTRACT

Plain-English Analogy: The digital land registry on Polygon. Every domain is an NFT recorded in contract 0xa9a6A3626993D487d2Dbda3173cf58cA1a9D9e9f.

In our Login SDK:
• ownerOf(tokenId): Checks who holds the domain NFT right now.
• expiryOf(tokenId): Checks if the domain expired (for .og, it returns 0 = never expires!).
• reverseNameOf(wallet): Returns which domain the user chose as their "Primary Display Name".

NAMEHASH

ALGORITHM

Plain-English Analogy: A barcode generator for names. Blockchains don't like storing long English text strings like akshat.og; they prefer 32-byte hexadecimal numbers.

In our Login SDK: Namehash takes akshat.og, normalizes lowercase letters, and hashes it recursively: hash(hash(".og") + hash("akshat")) $\rightarrow$ produces the exact numeric tokenId to lookup on Polygon.

Group 4: Cryptographic Tokens & Verification (JWT, ES256, JWKS, Pairwise sub)

JWT (JSON Web Token) & ES256

TAMPER-PROOF BADGE

Plain-English Analogy: A wax-sealed royal letter. Anyone can read the message inside, but if anyone tampers with even a single letter, the royal seal breaks and everyone knows it's fake.

In our Login SDK: An ID Token is a JWT signed using ES256 (Elliptic Curve Digital Signature Algorithm with the P-256 curve). It contains claims like name: "akshat.og" and wallet_address: "0x8FD5...".

JWKS (JSON Web Key Set) & /.well-known/jwks.json

PUBLIC KEYS

Plain-English Analogy: Publishing the official museum seal on a public billboard. Whenever a museum art collector wants to verify an artwork, they look up the seal on the billboard without needing to call the museum curator directly.

In our Login SDK: Endless Domains publishes its public verification keys at https://login.endlessdomains.io/.well-known/jwks.json. Game servers download and cache these keys so they can verify tokens offline at ultra-high speed without pinging our database!

PAIRWISE SUB (Subject Identifier)

PRIVACY STANDARD

Plain-English Analogy: Having a different pseudonym at every gaming convention you attend, so the conventions cannot secretly compare notes and build an invasive tracking profile on you.

In our Login SDK (Decision D2): sub = hash(client_id, wallet). In Endless Vault, your player ID is pw_9c1f.... In Endless Arena, your player ID is completely different!

Crucial Architecture Rule: Player accounts are tied to their wallet, not their domain name. Why? If you sell akshat.og next year, the buyer does NOT inherit your high score or your game save files!

Group 5: Infrastructure & Token Rotation (KMS, AppKit, Rotation)

AWS KMS (Key Management Service)

VAULT SECURITY

Plain-English Analogy: A physical military-grade safe that performs math inside the safe and never lets the master key leave the room, even if someone hacks the building.

In our Login SDK: Private signing keys are NEVER stored in a database or plaintext config file. AWS KMS holds the private keys and signs the JWTs internally.

REFRESH TOKEN ROTATION & FAMILY REVOCATION

THEFT DETECTION

Plain-English Analogy: An elevator keycard that gets replaced with a brand-new code every single time you swipe it. If an old, discarded keycard is ever swiped, the alarm sounds and the entire room lock resets immediately.

In our Login SDK: Every time the game refreshes a token, the old refresh token is destroyed and a new one is issued. If a stolen refresh token is ever used, the system detects a breach and instantly revokes all tokens for that player session.

APPKIT / REOWN / WAGMI

WALLET CONNECTORS

Plain-English Analogy: A universal multi-charger cable that works for iPhone, Android, and USB-C.

In our Login SDK: The library powering the wallet popup on login.endlessdomains.io. It supports MetaMask, Coinbase, Rainbow, and phone QR scanning via WalletConnect with zero hassle.
